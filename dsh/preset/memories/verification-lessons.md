# 验证纪律（v1 实证提炼，2026-09-24 mipstack MSS 事故）

> **求助索引（迷茫时刻快查——按危机类型，非时间序；最新条目在文末）**：
> 测试全绿但线上仍坏 / 用例覆盖看着很全 → ① ｜ 数字跨组件边界（对端可见的头字段） → ② ｜ 想引用「某某实现也这样」来免检 → ② ｜ 自洽注释读起来像规格 → ② ｜ 根因假设引用的代码事实全为真却仍可能错 → ③ ｜ 多路审查全数漏过同一处 → ①④ ｜ 回归测试该断言什么 → ④ ｜ 加了规则却没生效 / 该放哪一层 → ⑤ ｜ 改完文件行为没变 → ⑤ 生效副本在别处 ｜ 修复形式=给现有代码加对称壳 / 被修代码的次序可疑 → ⑥

条目（实证追加）：

① **生产默认配置与夹具的配置差异轴 = 盲区；green 只在该配置下成立**

- 事故：mihomo 默认 tun MTU 9000（`listener/sing_tun/server.go:192-194`，`tunMTU = options.MTU; if tunMTU == 0 { tunMTU = 9000 }`）。仓库所有 TCP 尺寸相关夹具都活在 ≤1500 或**对称** MTU：interop 矩阵确实含 9000（`interop/gvisor/link_test.go:356-363`），但两端同 MTU，于是对端 MSS 与本端路径预算永远重合；唯一使用非对称 MTU 的 `interop/gvisor/pmtu_test.go:24` 是 UDP 且 mipstack 固定 1500。「本端大、对端小」这个**生产形态在仓库里从不存在**。
- 后果：栈按对端通告的原始 MSS 1460 选载荷，时间戳 12 字节在载荷选定之后追加 → 40+12+1460 = **1512 字节带 DF** 进 1500 局域网被静默黑洞。用户可见症状是「开代理后 App 刷不出 B 站」，边界是 1512 而非 1492。
- 教训：**测试全绿只能证明该夹具配置下成立**。声明验证完成前，把生产默认配置与夹具**逐轴对照**（MTU/栈选择/开关/超时/缓冲区/路由模式），任何未被用例覆盖的差异必须显式声明为超出范围；否则它就是盲区。差异轴清单本身是可列出的，不需要判断力——这正是它比「测试镜像真实链路吗」这种靠感觉作答的问句强的地方。
- 承载层（2026-09-24 修正，见 ⑤）：事故形态是「实现编辑 + 测试全绿 + **有**独立观察者」，而 `kix-settle` 三条通道**全部排除该形态**（实现结算要缺 green；盲抽样要求 `!freshObserverSeen` 且改动面小；高置信提交要求 `edits===0 && !freshObserverSeen`），`kix-discipline` 的 turn-stopping 又只在「有编辑**无**测试」时响。真正会响的是**新增的 green 时刻提醒**（green 首次落到当前 edit generation 时单发，与观察者数量无关）与**成员角色文件**（reviewer 硬约束 / qa 门禁项）——教训必须落在事故形态下真会触发的通道里。
- 反证：修复后新增的 6 用例回归测试在**未修复代码**上只有 jumbo 三格失败并打印 1512/1524，而 1500/1492/IPv6-1280 三格照样通过——同一测试同时证明「bug 存在」与「旧夹具为何看不见」。

② **跨组件边界的数字，权威是外部实现不是本地注释**

- 证据：`tcp.go` 原函数注释把错误语义写成了设计意图——「applies peer MSS to data only, while charging extra TCP options exclusively to the current path's header budget」。代码与注释**自洽**，逐行找逻辑错误的人看到的是一个自洽的设计决策。唯一能推翻它的是外部权威：RFC 6691 的 MSS 定义（MTU−40）要求选项从数据预算里扣，Linux `tcp_current_mss` 正是 `min(对端 MSS, 路径 MSS) − 选项`。
- 判据：一个数字若会出现在**对端可见的头部字段**里（MSS/窗口/PMTU/分片尺寸），就至少取一条跨厂商或可重放物证通道对齐；**注释是假设，不是规格**。这类 claim 属于「外部语义密集」，本应命中常驻层已有的跨厂商条款——漏的不是规则，是**分类**：没人把它归成外部语义 claim，规则就没被武装。跨厂商通道存在但没被路由过去时，等于不存在。
- 配套（2026-09-24 第二实例）：**为「不做」辩护的 claim，证据标准必须与为「要做」辩护相同**。当日残留笔记写「地板边界 unreachable in practice, matches Linux」——四个断言里两个是假的：算术（100/88）对不上树里常量 `tcpMinimumPeerMSS = 48`（真实是出线 60 vs 通告 ≤59），「matches Linux」方向相反（torvalds `tcp_output.c:2007` 先 clamp 后扣选项，注释自陈 "mss_clamp does not include tcp options"）。「matches X」给不出函数名/行号就当未知。

③ **被所有假设共享的事实不是证据**

- 证据：错误的 ICMP PTB / PPPoE 黑洞框架引用的代码事实**全为真**（`forwardICMP` 丢非 echo、`EMSGSIZE` 不入栈）。但它们被 system 栈与 gVisor **同样共享** → 无法解释「只有 mips 坏」。这个框架在被用户两次推翻前消耗了整整一轮排查。
- 判据：给每个根因假设配一句**判别器**——「若此假设成立，哪一处观测会与替代假设不同？」测不出差异就不是证据。上例的判别器只有一句：这个事实能区分 mips 与其他栈吗？一句话即可作废整轮。
- 推论：真实但**非判别性**的事实最危险，因为它在证据账本上看起来像进展。

④ **回归测试要落在未被覆盖的那根轴上，且必须在旧代码上红灯**

- 证据：6 用例回归测试（`tcp_segment_size_test.go`）在未修复 HEAD 上给出 `payload plus options = 1472, exceeds advertised MSS 1460` 与 `emitted IP length 1512 exceeds the 1500-byte peer link`；修复后全绿而控制格前后皆绿。
- 判据：断言数量不计价。一个回归测试的价值 = 能否在旧代码上失败，且失败**只亮在出问题的那根轴**上（控制格保持绿，才证明测试测的是那根轴而不是运气）。写完先跑一遍旧代码，没红灯就说明它锁不住任何东西。
- 配套：断言要直接编码外部不变量（此处为 RFC 6691 的 `载荷 + 选项 ≤ 对端通告 MSS`），而不是编码实现的当前行为——后者会随实现一起漂移。

⑤ **选承载层前，先用事故的触发条件把候选通道逐个代入——否则等于零效果**

- 事故（2026-09-24 当日）：把 MSS 教训先放进 `kix-settle` 盲抽样文案，随后被用户点破——**该通道对本次事故形态结构性失明**（`kix-settle.js:284` 要求 `!freshObserverSeen`，而事故会话有 9 个观察者；实现结算要缺 green，而当时全绿）。改动真实、测试真实全绿、对目标缺陷却零覆盖。
- 判据：选通道时写下事故的**具体条件**（有没有实现编辑？有没有 green？有没有 fresh observer？是不是长任务？是不是审查会话？），逐个代入候选通道的触发谓词，写出「会响 / 不会响」。**不代入就等于把规则放进死信队列**——这比不写更糟，因为它制造已被处理的错觉。
- 推论：拉取式记忆（`experience`）只在「卡住」时被人想起，而配置轴盲区的特征恰恰是「一切正常、看起来完成」——**越是不觉得需要查记忆的时刻，越是这类缺陷存在的时刻**。所以该族教训的常驻承载层必须是**推送式**（green 时刻、分派时刻、门禁时刻），不能只靠 pull。
- 同族：这与 ①（存在性 ≠ 可观测性）同构——**写进某个通道 ≠ 在该形态下会触发**，与「验证跑了 ≠ 守卫能消费」是同一个错误在两个层次上的表现。
- 当日第三次实弹（同一错误的另一层）：把配置轴条款写进 `agents/kixpower-reviewer.agent.md` / `kixpower-qa.agent.md`——**这两个文件不进派发路径**。真正作为 persona 注入成员的是 `agent.cordis.yml` 里对应成员档（`toolName: subagent_reviewer` / `subagent_qa`）的 `persona:` 快照（`agent.cordis.yml:611` 注释自陈：单一权威在 .md，此处是可注入的精简快照）。**改了权威文件 ≠ 改了生效副本**：三处并行（settle 通道 / 角色文件 / 生效快照）连续三次踩同一形态，说明这不是疏忽而是缺少判据。
- 已机械化：`kix-consistency` 新增 `member-role` 分类——写入 `agents/kixpower-*.agent.md` 即提醒「生效副本是 agent.cordis.yml 的 persona 快照，只改本文件 = 零效果」。判据是**路径**（确定性）而非内容（模糊），故无假阳性。
- 推广：任何「权威文档 + 精简副本」双层结构（persona/快照、schema/迁移、契约/实现），**先确认哪一份会被消费**，再动手改。

⑥ **被修代码不是修复形状的权威——语义修复的锚点在缺陷载体之外**

- 事故（2026-09-24 第二段）：修 MSS 语义缺陷时，补丁形式是「给现有模式补一个对称项」——被修代码在路径侧「先扣 12 再钳制」，补丁就给对端侧也「先扣再钳」（`clampMSS(tcpAdvertisedDataMSS(...), localMaximum)`）。但被修代码的次序本身是缺陷的一部分：先扣后钳让 `tcpMinimumPeerMSS=48` 地板把已扣的选项重新抬回去（出线 60 > 通告 ≤59）。上游修法先把 RFC 9293 公式写下来——`min(对端, 路径)`，选项在 min **之后**扣，即 Linux `tcp_mtu_to_mss` 的次序（torvalds `tcp_output.c:2007` 注释自陈 "mss_clamp does not include tcp options"）——形状取自外部权威而非现有代码。
- 判据（触发器）：修复的形式是**给现有表达式加壳 / 补对称项**时，停一拍问：这个表达式的形状（操作次序 / 分解方式 / 变量含义）是不是缺陷的一部分？**缺陷代码是「发生了什么」的证据，不是「应该发生什么」的证据。** 语义修复的锚点三选一且必须可引用：线上实测（字节）、规范公式（RFC 节数）、参照实现（函数名）。给不出引用位置的锚点等于没有锚点。
- 反过度泛化：**不推导出「推翻重写」**。diff 仍可最小——两种修法主线等价、都可最小 diff，本质差别只是锚点（一两行）。约束的是**语义从哪来**，不是**改动多大**；最小 diff 不背这个锅。机械性修复（补一个缺失的检查/守卫）不触发本条。
- 同族：与 ② 同构（权威在当前工作物之外）；与根因阶段「跳出假设框架」（ICMP 帧被抓包实测推翻，见 ③）是**同一原则在两个阶段的表现**——假设的锚点是实测，修复的锚点是公式/参照。当次两个阶段各违反/执行了一次：根因阶段靠用户点破跳出，修复阶段没人点破于是踩坑。
- 承载层与残余：语义判断 → memory（无机械触发器可判「这个 edit 是语义修复」）。诚实残余：这会重演 ⑤ 指出的 pull 通道问题。falsifier：若复现为「对称补丁修语义缺陷后边界仍错」，升级为把触发器那一问并进交付三问（push 面）。
