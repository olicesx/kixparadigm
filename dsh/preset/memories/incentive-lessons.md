# 激励面实证教训（EXP1–EXP3，2026-08-19 冻结）

> **求助索引（迷茫时刻快查——按危机类型，非时间序；最新条目在文末）**：审查 LGTM/高置信提交未派独立观察 → ⑯ 换结算信道，别往索引加条目 ｜ 想靠缩短契约换审查深度 → ⑯ 注入内容不是杠杆 ｜ 任务改不动 → ① 契约清晰度 ｜ 交付前犹豫验证 → ② 按零结算 ｜ 想写激励/劝诫 → ③ 劝说层已证死 ｜ 含糊任务 → ④ 先显式化契约 ｜ 想加新机制 → ⑤ 三类合法落点 ｜ 没测度 → ⑥ 先给测度 ｜ 工具没人用 → ⑦ 拉取式+有用才活 ｜ 没对照 → ⑧ 预注册+盲审计 ｜ 配套被裁 → ⑪ SHA 口径 ｜ 恢复记忆留什么 → ⑫ 工具无关性 ｜ 改完怕悬空 → ⑬ 双向引用 ｜ persona 选人 → ⑭ 指派句是决策代理 ｜ 临时绕行转正 → ⑮ 显式退役条件 ｜ 用户说半价档没脑子 → ⑰ 包装两可 ｜ 缩减常驻把哲学和货架一起砍 → ⑱ 选择压不是常驻税

条目（实验锚定，实证追加）：

① **契约清晰度是反证行为的第一瓶颈**（EXP3 主结论）。同一模型同一 plain 激励面：歧义契约 16/16 同错（EXP2-T2"preserve API"被全员读成保全 list 返回），无歧义契约 24/24 全过隐藏陷阱（ujson import 期执行/TypeError 立即性/严格编解码四边缘）。投资排序：契约清晰度 >> 机制 >> 文本。自己动手前先问：这个任务的行为契约里，"必须不变/必须改变/必须成立"写清楚了吗？没写清楚就去写清楚或问，比任何验证机制都便宜。

② **无执行证据的结论按零结算**（EXP1 三臂共同结构）。报告可以完全正确而实现错位——每次让裁决变真（可重放 battery/盲审计/verify 脚本），缺陷几分钟内被抓。交付时每个关键判断只按可重放证据计价；环境限制无法执行时，显式声明未验证点及其影响（这是诚实的结算，不是失败）。

③ **劝说层证死**（EXP2+EXP3，三轮）。把反证定价/新颖性租金/搬迁审计写进 persona：零行为分化（EXP2 Δ=0）、零质量增量（EXP3 Δ=0）。激励不活在 prompt 里，活在结算层——想让行为变，让说谎变贵、让隐藏变贵、让测量变免费，不要把话说得更好听。

④ **歧义是共同失败模式**（EXP2-T2）。"preserve the public API" 与 docstring 的生成器承诺冲突时，16/16 个 run（含参考臂）一致选择保守解读并牺牲文档承诺。契约里每个行为词必须无歧义；发现两可解读时，要么问用户，要么把选定的解读显式写进交付说明。

⑤ **机制的合法落点只有三类**：工具（补盲点，如 probe）、结算信号（交付时 steer，如 kix-settle）、记忆（拉取式经验库，如本文件）。第四类"prompt 里的认知规则"已证死。新机制先问：模型变强后它还有价值吗？没有就进 memories 不进机制。

⑥ **不测量就看不见**（EXP1+EXP3 存活缺陷的共同类）。成本搬迁（重解析/首调用）、环境掩盖（flox import 期执行）、延迟校验（TypeError 推迟到 next()）——全部只在测度下现形。修任何"性能/行为"问题前，先拿到 Δ墙钟/Δ峰值内存/调用计数的基本测度；probe 的 measure=true 和 duration_ms 是为此免费附带的。

⑦ **拉取式，有用才活**（EXP3 工具行为）。模型无工具仪式性滥用：no-op note 安慰剂 48 run 零调用；probe 采纳时先探测后修复（步骤 11–15 扫边缘 vs 修复在 16）、零成本溢价（1.00×）。教训：工具做成可选能力+中性描述，不强制、不菜单注入、不在 persona 里推销。

⑧ **结果要用冻结判据结算**（EXP2/EXP3 方法论）。预注册判据→陷阱先行物理验证→交错盲测→冻结 patch→机械 battery→脱敏跨厂商盲审计→一键 verify 脚本。两轮均抓到"实验者自己"的错误（种子断言 25≠31、校验器 13 处 bug）——实验者也是被结算对象。写实验/评估类任务时照此管线，判据冻结后不可改，勘误留痕。

⑨ **机制归因要同模型双臂闭合，且机制有价格**（EXP1-R2，2026-08-20）。单臂跨模型的"修复"不能归因机制——flash 单臂四盲点全好后，同模型双臂才发现：v2 精确复现 EXP1 的 flox 残留（stub=1）、三件套修复（stub=0+传递链显式处理），归因才闭合；而 E3（race/delayed）双臂同过，修复属于模型代际——不抢机制的功。同时量出代价：机制深验证 ≈2.3× 墙钟（148 步 vs 84），与 checklist 同价位。**成本分层**：契约清晰 → 激励面（½价）；隐含契约 → 机制（2价换覆盖）；文本劝说 → 0效果。归因纪律：复现组必须与原始实验同 preset sha、同 prompt sha、同基线 commit，任何一环漂移归因作废。

⑩ **改插件必须换 preset 名或重启宿主**（2026-08-20 宿主缺陷实证）。dsh 按 preset 名缓存插件快照——磁盘修复不生效，会制造"修复无效"的假象（本轮 11 次判别实验的矛盾时间线全部由此解释）。同理：post-execute 事件 handler 必须透传链返回值（`return next()`），返回 undefined 在部分适配器下破坏 tool-result 拼装。调试插件行为时先用「同字节换名」判别缓存与真实现。

⑪ **配套记忆是实验血统的一部分，SHA 锚点只盖 agent.cordis.yml**（2026-08-20 版本核对实证）。实验冻结的 `compositionSha256`（如 49f820…）复算口径 = 仅 agent.cordis.yml 的 SHA-256，**不涵盖** memories/agents/skills/instructions/prompts 配套目录——SHA 一致 ≠ 配套一致。v1.3.0 重排把默认 preset 的 memories 从 6 个裁到 1 个（只留本文件），且 persona 仍引用被删的 orchestration-lessons.md（悬空引用）。核对纪律：验证实验/发版一致性时，除 composition SHA 外必须单独盘点配套目录清单与 persona 引用的存在性；「配置哈希相同」不能替代「配套存在」。

⑫ **记忆按「工具无关性」裁剪，状态史不进化石层**（2026-08-20 恢复执行）。恢复被裁记忆时：①原样恢复被 persona 引用的文件（悬空引用必修）；②机制事实层（能力地图/任务映射/方法论）保留，已落地的逐版验收状态史删除（状态史看 CHANGELOG，化石层只留危机时刻有用的判断）；③工具特定坑（具体库/框架/旧工具名）不占默认面，完整版留 classic；④恢复动作本身在文末留痕（本条即出生证明）。原则复用：记忆是迷茫时刻的灯，不是顺境时的规则——「有没有人在危机时刻被它救到」决定去留。

⑬ **引用完整性核对必须双向：资源存在性 + 引用性质分类**（2026-08-20 恢复后复核实证）。恢复记忆后逐条核对全部引用：①**运行时依赖**（persona/记忆指引模型去读的文件/工具）必须存在，缺失即修——本次 persona 三处悬空引用（skills/pwsh-reliable、agents/*.agent.md、prompts/kixpower-*/instructions/）按「裁剪引用、保持最小面」处理（原理句替代硬路径，配套留在 classic）；②**证据标注**（记忆里说明经验来源的仓库文档/脚本，如 kix-optimization-implementation.md、audit-delegation-history.cjs）只需来源存在，不引入 preset——它是 provenance 不是依赖；③**历史叙述**（描述当时验证过的命令/工具，如 kixst 三命令）不需当前存在，但涉及插件时要确认插件本身在位。核对清单：persona 引用、记忆互引、插件引用、技能/agents/prompts 路径。纪律：改配置/恢复配套后必须跑引用存在性检查，防「恢复了一个、悬空了另一个」。

⑭ **persona 不替模型选成员——指派句是决策代理+双源负债**（2026-08-20 成员分配裁决，v1.3 哲学四判据交叉）。默认激励面 persona 曾复述成员职责（"dev=Nova/Sage/Milo 三合一…；qa=Ivy…；reviewer=反方辩护三层"），按四判据判死并删除：①⑫ 文本通道是危机通道——指派句日常零阅读白占常驻 token，危机求助对象是 memories 非指派句（死文本）；②⑩ 激励面决定菜单可见性、修复后混合档自然涌现（T4 自发 reviewer+cross）——指派句把 v5.5 涌现固化成职能枚举天花板（⑨ 第三种过拟合，前两种已拆）；③成员契约已内聚在成员档 persona（spawn 时注入）——主 persona 复述=双源（lite 平台条件化漏改同款事故模式）；④成本分层——825 字节常驻税违背最小认知层。**保留**：菜单可见性一句（ACTIVATABLE 档不被 persona 提及则模型不知其存在）、四条地板（原理层）、current_sprint 交接元数据（机械 gate 依赖）。**选择压四落点**：kix_capability_search 目录（决策时刻全菜单）+ 成员档契约内聚（单源）+ 地板原理句（环境遗传）+ orchestration-lessons ⑧（四档分化实证，危机拉取）。配套机械修正：kix-browser 常驻化后 kix4 parity 断言 +3→+4、null 变体补同步 browser 行（常驻化的第二处双源漏改，被 parity 测试当场抓获——守卫有效性的实证）。晋级判据：后续真实任务观察「成员选择召回率」——若模型自发组合退化（不再用成员档），本条裁决重审。

⑮ **「验证过的路径不回退」是 status quo 偏置——过渡态必须显式标注退役条件**（2026-08-20 kix-browser 常驻化范式审计）。kix-browser 常驻挂载的出生证明是宿主缺陷（effect 花括号注册瞬间注销工具）；bug 修复+回归单测在位后出生证明失效，但注释以「验证过的路径不回退」把绕行方案封为终态——范式审计：当时验证的是「绕行可行」（症状消失），从未验证「修复后的激活路径可用」（病根治愈）；这句话把「绕行没死」偷换成「绕行是终态」，任何临时绕行写上它都会变成永久机制（⑨「给进化的东西上石膏是负资产」的养成路径）。**判定**：常驻不违背拉取式⑦（EXP3 note 48 run 零调用——常驻工具模型也不会仪式性滥用，税只是 1KB schema），但违背最小面方向性；正确形态=**为不确定的激活故障买验证，不买常驻**。**操作纪律**：①绕行性挂载必须注明「过渡态非终态」+ 显式退役条件（本次：激活路径 E2E 复验通过→注释回退渐进披露；复验不过→出生证明更新为第二轮实测）；②「理论已恢复」不等于「已恢复」——单测级修复需 E2E 闭环才算路径可用；③低频工具的常驻 schema 税是每请求确定性成本，激活风险是不确定成本，激励面哲学给后者买保险的方式是补验证而非付常驻税。

⑯ **拉取式记忆对高置信提交时刻失明——修法换信道，不往索引加条目**（PR#33 审查实验，2026-08-21，merry PR#33，glm-5.2，n=1 PR / n=1 仓 / 单模型）。预注册对照：4 个 fresh 评审人全部 request-changes，唯一 LGTM 来自写过结论的主代理；4 人产出 3 个互异且核验为真的缺陷，零重叠。H-indep（独立性）按预注册规则胜出：B 臂 1/3 命中同一 anchor，肥契约不压制深度。拉取式经验库在发布 review 前未被查询——全程无迷茫就不查；一条未查证平台断言混入结论（碰巧措辞合规）。**操作含义**：①独立性是验证杠杆，注入内容（83 行派生 vs 551 行真契约）不是——对抗角色继续用现成契约，不为此裁剪注入；②高置信提交（审查 LGTM / 无编辑交付）必须走结算层，kix-settle v2 在终稿像审查结论且未派独立观察者时 advisory 单发；清账=派过 subagent/cross/reviewer（含 capability_call 代理）；③消费对抗 finding 时 owner 复核严重度（4 条里 2 条经复核应降级：机制事实 ≠ finding 成立，处置轴 ≠ 缺陷轴）；④契约二分仍是 candidate：可推导半（命令/结构/测试锚定）agent 可零虚构自作者，主人默会半（git 工作流/哲学/政策）恢复≈0——不升格为机制，危机时刻才查本条。C 臂被决策规则杀死，零注入下限未知。

⑰ **产品包装两可与任务契约两可同构——名字必须等于注入**（Bradford 2026-08-21，candidate）。用户研究「快长脑子」的 kix 后改用 classic：「省钱的那个效果不太好」。决策时刻信息：点 `kixparadigm` 的 picker 曾写「质量持平经典版、成本约一半」；真源是效用准则 + probe/settle/experience，三通道全文 `disabled`，skills/agents 目录不在。EXP1 ½ 价同质量测的是契约较清的 SWE，被结果导向收养成产品默认（防 resulting 候选的毒药象限）。**已做（信息工具）**：picker / README 第一屏诚实标注两档差在哪；不改默认名。晋级条件：再 2–3 个真实用户、任务属性可分类。回收条件：标注后错配消失且无人再把默认当范式本体。

⑱ **缩减常驻层 ≠ 砍掉选择压——核心哲学是土壤，货架是按需**（Bradford 后续 + 用户 2026-08-21）。激励面转正时把活 persona 收到效用准则，同时 `skill-filesystem disabled`、不随附 skills、菜单可见性⑭ 那句也不注入。结果：成员档仍可激活但无人去搜；`experience` 描述还指向 skill，目录是空的（⑬ 同款）。用户判断：关掉的内容里有真东西，该突出选择压而不是砍核心哲学。**已做**：活 persona = 压缩锚点（三通道/二相性/规则是负债/三检信号/写码前）+ 效用准则 + 属性路由/菜单/skill+experience 指针；启用 skill-filesystem；默认档 `skills/` 相对链接 classic 货架（仓库单源，按需，648K 不进常驻）；`kix_capability_search` 增 `kix-surface` 组（空查询第一组：skill/experience 直呼 + 成员档激活 + slash hint）——目录是信息工具，不是常驻说明书。**明确不做**：启用死 persona 双注入、搬 `agents/*.md`（与 ACTIVATABLE 双源）、把编曲说明书灌回常驻、改 null 消融面、改默认名、打开 kix-budget。死亡条件：两轮真实任务 skill 零调用且质量不降 → 货架可再关；成员召回率不升 → 删菜单一句；`kix-surface` 组零调用 → 收回该组。常驻预算实测 2070 chars / ~630 tok（上限 4500/2600）。
