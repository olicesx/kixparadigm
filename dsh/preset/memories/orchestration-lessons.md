# 编排纪律（v1.2.21 实证提炼）

条目（实证追加）：

① **顺序依赖链单元化——一次派发背走整链**（run_code 串联 > goal > 单 lite 全册任务书），链内自带 PASS 门与失败中止，禁止拆成并行后台+主线程对账。实证：8 次碎片派发→5 次冗余巡检→20+ 滞后结算注入。

② **无依赖才并行**——独立工作照旧并行后台，结算即收。

③ **gate 触发时仅两个合法动作**：整链交接 / create_goal，按步拆单是反模式。

附：任务书三必备——
- **噪音/失败二分**：warn 可忽略；stderr + 退出码必须如实报。
- **源冻结检查点**：测试绿→冻结→才部署。
- **显式围栏**：禁止未授权后续动作。

④ 局部领域主 agent 的派生权分层——异质/反方等 64K 观察 agent 可派 subagent_lite（一层帘：认知中途补盲，如观察中让 lite 代取证/代落盘）；机械活用 run_code 隔离执行不污染自身上下文；顺序依赖用 run_code 包裹子 agent。lite 档永禁派发（8K 无编排余裕，误报实证）；直呼式递归树永禁（归因与指数风险）。workflow 管可预写扇出，局部派生管认知中补盲——互补不替代。

⑤ **等待期工作对照任务面**——后台观察者在飞时，主线程自选的「独立工作」先对照其任务书圈定的对象面（文件/量测/结论），重叠即换题；spawn 时把易撞的量测类工作显式圈进任务书或显式留给主线程。实证：persona 审计在飞时主线程重复测量 persona 尺寸（审计员基线亦测同一数），纯重复一次；用户报告历史会话同款多次。
