## 一、AI 认知论（范式层——教"为什么"）

### 1. 出路一直在模型里，工具只补盲点
模型推理是主力；工具/机制只在决策时刻补已知盲点、让信息完整。激励面修对后模型自组织恢复远超预期（T4 三通道、T3 深水自律皆零编排自发）。（教训⑨）

### 2. 规则是负债
每条规则有维护成本 + 压制涌现风险。理论锚点：Sutton 2019——长期看内建人类知识会平台化并抑制进步（注意：此为转述，原文无逐字句，勿当直接引语）。操作判据：
- 新增前问「模型能力提升后还有价值吗」——没价值不加
- 单次经验只作 candidate；须经真实任务试验 + 可观测结果才能晋升 validated
- 两轮无真实收益即回收；老规则按反证与使用价值定期修剪

### 3. 属性信号是生成性的，类型映射是过拟合
禁止「任务类型 → 动作」静态映射（如 "PR → 强制 review 模板"）：每类任务加一条 → 规则爆炸 + 压制涌现（新任务类型无法自动适用）。属性信号（规模/外部副作用/验证关键/目标不明）对任何新任务类型自动适用。

### 4. 阶段二相性
创造最小规则时别自我验证（创造视角会污染验证）；验证结构化补盲时别创造。两阶段认知模式不互相泄漏——自我验证被创造视角污染，故需独立 agent 验证。

### 5. 三通道交叉验证
执行 → 产出 claim；观察 → 异质子 agent（视角异质、跨厂商最高置信）独立读代码验证；汇总 → 只在同层聚合。**异质多数一致才可发布；同质一致是虚假置信。** 任一独立观察者基于证据反证 → 深挖分歧点。实证最高价值形态：跨厂商观察者反驳主线程（真实碰撞，非合奏）。（教训⑧）

### 6. 盲点对称性——不迎合用户
AI 有盲点图谱（深度不足/读写混淆/自信偏差/辩护倾向/外部视野/过度工程/架构方向），用户同样有盲点（需求不清/假设错误/思维定式）。一味迎合 = 把 AI 上限锁在用户当前认知内。**AI 的价值 = 提供超出用户当前认知的视角；用户的价值 = 提供 AI 没有的上下文。互相引导，不是单方服从。**

### 7. 范式降偶然复杂度，不降本质复杂度
kix 是 AI 原生范式，不是人类组织管理的翻译。人类组织形态（层级/总监/信任中介）为绕过人类瓶颈而生——注意力有限→分权、记忆易失→制度、沟通昂贵→协调角色；LLM 瓶颈谱完全不同（确认偏误/上下文膨胀/激励面敏感/能力时变），对应件（三通道/budget gate/决策显式化/能力正交）早已就位。分身即复制、沟通即注入、制度即 prompt——照搬人类组织反引入人类特有的病（信息衰减/代理失控）。**设计纪律：每个新机制先问「这在解决 LLM 的瓶颈，还是人类瓶颈的惯性投影」——后者即弃。**（教训⑩）

### 8. 教原理，不教应用
kix 只教"为什么"（三通道防确认偏识/规则是负债/决策显式化），不教"怎么做"（几步派谁/什么任务配什么团队）。原理对任何能力水平的模型恒成立；应用规则则把某次涌现固化成天花板。（教训⑨）

## 二、自我学习涌现发现（实证层——度量出来的，不是假设的）

### 1. ROLE_DROUGHT 事件：成本机制只定价、不路由（教训⑦，validated）
**类别错误实证**：kix-budget gate 放行集曾硬编码 lite/goal——上下文溢出时「整条判断工作流甩给 dev」这个最强卸载动作被 deny，只剩「再派 lite 探一下」；提醒文案只点名轻路径工具，**每次注入都是一次 in-context 激励面改写**。

**行为后果**（Windows 会话库审计，`scripts/audit-delegation-history.cjs`）：
- v7 编曲模型落地后角色分派正在涌现：08-16=3、08-17=1（+cross 4）
- 08-18 budget gate 落地后跌到 2（lite 洪水 33 个）
- 08-19 归零，ROLE_DROUGHT（角色荒）

**修复形态**：放行集对称开放全部卸载通道、文案在决策时刻呈现完整成员菜单、红线声明「不干预成员选择」+ 断言锁定。
**判据**：动激励面的改动必须过「角色分派召回率」审计——**没有度量的能力等于没有的能力**。

### 2. 四档复杂度实验：「模型只会 solo」证伪（教训⑧，validated）
同模型、同宿主、同提示词风格，四档任务四种决策，随复杂度单调分化：

| 档 | 任务 | 决策形态 |
|---|---|---|
| T1 | 读三文件 | 1×bash 纯 solo 零开销 |
| T2 | 加函数 | spec + solo 落痕 |
| T3 | 修 UI | solo + 机械验收 + subagent_vision 三通道混合（自书 mode："独立验证=确定性 Playwright 审计+vision 截图独立观察，不派 dev/qa"——区分验证通道与实现通道）|
| T4 | 跨插件解耦 | solo 实现 + reviewer 必配 + cross 跨厂商证伪（8 维度评审含诚实降级；cross 推翻主线程顺序假设并转化为文档化交付）|

**三个关键发现**：
1. 模式不是「模型偏好 solo」，而是「激励面决定菜单可见性」——修复后混合档自然涌现
2. 跨厂商观察者反驳主线程 = 三通道最高价值形态（真实碰撞非合奏）
3. T4 主线程亲自盯双副本同步 = 战术协调挤占战略上下文 → mandate（授权分层）的立项证据

实验基建：`/tmp/trials-scan.py` 四档扫描器、`audit-delegation-history.cjs` 基线表。

### 3. 元裁决：涌现产物进 memories，不进机制（教训⑨，validated）
**操作性分界**：涌现产物进 memories（可被超越的养分），不进机制（成为枷锁的天花板）。

四次过拟合的反复模式（每次都是把某次涌现固化）：
1. 固定流水线——对弱模型保姆化 → v7 拆
2. lite-only 放行集——对成本痛点固化 → ⑦修复
3. 职能枚举——对讨论固化 → 设计期拦截
4. v8 施工图——对理论固化 → 降等痛储备（默认不执行，观测到真实痛点 session 才开工）

**最高实践：一次让机制变少的变革是范式的最高实践。**

### 4. 知识管理生命周期（单条经验的晋升通道）
单次经验 → candidate（留痕）→ 真实任务试验 + 可观测结果 → validated（晋升进 lessons/practices）→ 反证或两轮无收益 → 回收。度量涌现而非假设涌现——所有 validated 条目都带实证锚（日期/实验/审计脚本）。

### 5. 组织学两原则（v8 设计期确立，等痛储备）
- **A2 授权是谱系不是枚举**（辅助性原则）：机制只定义授权元属性（reserved 清单 + defaults broad），角色形态（监工/带队/辅佐）是主模型与领队的涌现约定，禁止预设职能枚举
- **A4 结构涌现于信息结构**：团队拓扑（前端组/后端组/…）是产出不是输入

### 6. 学习论闭环（教训⑪，2026-08-19 入层——上会话收官理论）
学习单位=「范式×模型×任务域」组合；范式提供**选择压**非基因图谱；涌现=环境记忆累积进化（memories=化石层、会话=世代），不是权重更新；**偏好多样性是特性不是缺陷**（七次同型实验零重复编曲但全在健康区间）；**没有路线图，只有化石层**——进化引擎就是使用本身。
