## §2 Mechanical guards (resident)

- `plugins/kix-guards.js` auto-mounts a `tools/pre-execute` listener (scope-filtered to this preset) that intercepts: destructive SQL (DROP/TRUNCATE/DELETE/UPDATE without WHERE, statement-level, comment-stripped; terminal DB clients require command-position detection + SQL payload analysis, so `echo "psql DROP"` no longer trips), dangerous git (force push incl. `-f`/`+refs`/`--mirror`, main-branch pushes, commit-budget via reflog subject — commit-type entries only, stale-sprint fallback to max-numbered dir, plan.md max_commits fallback chain, cold-start warn; v7), control-plane file writes (v8: write intent only — `grep/cat/ls ~/.dsh` are allowed; v11: source-repo `dsh/preset`/`en/preset` exempt; v12: install-root writes remind-and-allow so self-iteration can update `~/.dsh`), unknown execution tools, MCP GitHub remote writes without a feature branch (tool prefix configurable via `githubToolPrefix`). v9: publish/comment/ordinary-push confirmation gates are soft constraints — explicit user instruction is the decision and no per-operation question is asked; hard deny remains for irreversible destruction only.
- Human-decision soft constraint (v9, v1.2.11): publish/comment/merge/destructive actions are off by default; an explicit user instruction ("comment on the PR") is the decision and executes directly. `ask_user_question` is reserved for genuinely missing decision information. Hard deny remains only for mechanical irreversible destruction.
- run_code code-body scanning retired (v18, v1.3.10): KIX no longer token-scans or trims Node/JS native capabilities. The DSH worker supplies containment, not a security boundary: a fresh isolate per run, `env={}`, CPU/wall/heap/output limits, and hard termination; nested `tools.*` calls still pass through the full pre-execute pipeline. Native fs/network/child_process now carry the same trust as bash and are not audited as separate actions. Residual boundary: terminating a worker does not guarantee cleanup of OS processes it spawned.
- The harness's sandbox stack is the resident mechanical layer on top; the approval policy for `danger-full-access` is `never` (fully automatic, no approval dialogs).

## §3 Delegation, cost tiers & vision

- **Cross-vendor observer**: three-channel observation / highest-confidence claims / platform-library semantics assertions → `subagent_cross` (GLM-5.3, cross-vendor contradiction). Ordinary dispatch → `subagent` (inherits the main model). `workflow`'s `agent(prompt, {provider, model})` overrides per call. Since v5.9 the cross/vision/thinker rows pin only a `kix-route:<tier>` sentinel model name; `plugins/kix-route.js` resolves it in the child's first agent/request waterfall against the live llm catalog — cross = vendor inverted from the parent, vision = first model declaring image input, thinker = deepseek preferred. **Boundary semantics (v5.9.1: fail when the role's core capability is missing, degrade when the role still stands)**: cross in a single-vendor deployment (no foreign provider registered) and vision with no image-declaring model anywhere FAIL AT START — the error lists registered providers plus what to do instead (plain subagent same-vendor review with an explicit caveat / configure the provider) and reaches the parent via the failed run; never silently degrade to same-vendor (false independence is worse than failure). Thinker without deepseek degrades to the environment default route (the big-budget deep-thinking role still stands) with a one-time warning; resolution failures are not cached (a provider registered mid-session takes effect on the next request); a cross child that hits a provider-availability failure retries in place on distinct healthy foreign providers (default at most two failovers, configurable via `crossProviderFailovers`; exhaustion alone is terminal zero evidence; context/request errors do not switch providers); a missing plugin fails LOUD on the sentinel (UNKNOWN_MODEL). The old "exact pair" rule was a declarative-layer constraint (agentOptions custom keys are stripped by zod); the waterfall layer can rewrite the whole config (kix-cost's lite fallback proved the same seam). The candidate pool is the `llm-pi-ai:` list of `settings.yaml` plus the pi-ai built-in catalog; model-line upgrades only touch settings.
- **Cost tiers (v5.8)**: `subagent_lite` = slim composition (mechanical persona ~60 tokens shadows the ~17k resident persona; `toolFilter` trims 82 tools / 17.2k tokens down to read/grep/glob/pwsh / 1.6k tokens) → per-step fixed overhead ~34.3k → ~5.9k tokens (↓83%, measured). It pins no provider/model — the child inherits the parent agent's route, so it needs no particular cheap model to exist. `plugins/kix-cost.js` keeps its auto-probe/fallback branch, dormant by default: it fires only when a deployment pins its own lite route with an explicit `provider`/`model` (`llm.listProviders` + `resolveModelInfo`; unavailable → fall back to the environment default route via `agentDefaultModel.currentSelection()`). `subagent_thinker` (deepseek-v4-flash, 128K cap) is the same-family max-effort tier.
- **Effort normalization (`plugins/kix-cost.js`)**: deepseek children without an explicit effort get `reasoningEffort` injected by budget cap — `subagent_thinker` (≥98K) → `max`, others (64K) → `high` (the adapter default is high/256K; the 64K cap is the runaway guard). GLM children are adapter-managed; the main session (explicit effort from `settings.yaml` `agent-default-model.reasoningEffort`, default `high`) and any explicit per-session selection are never touched. Runs on the `agent/request` waterfall; unit tests: `node plugins/kix-cost.test.js`.
- **Vision**: models that declare image input can use native `read_image`. For a text-only main model, pass an image path and question to `subagent_vision` when needed; it routes to a model declaring image input. The host retains its own capability checks.
- **UI image upload**: `dsh-vision-bridge` converts images only for a confirmed text-only current provider/model. Image-capable models submit natively, bypassing the bridge's 8MB limit, base64 reads, description requests and draft/image changes. Unknown, failed or unsettled capability selection also uses the native host path. A local `/api/dsh-vision-bridge/capabilities` query reads host metadata without images, vision credentials or inference; the ordinary model directory does not expose input modalities. Model changes invalidate cached results, and stale conversions cannot alter newly selected images. Successful text-only conversion retains the `📷 [图片自动识别]` prefix; conversion failure retains the original images. Enter keeps its existing native submission behavior.
- Both `subagent_cross` and `subagent_vision` route through `llm-pi-ai.providers` in `settings.yaml` — see §Settings.

### §3.1 Subagent result-return channels (2026-08-17, field-tested)

Background (continuable) children have two return channels. Mechanism facts from dsh-subagent source (`notifySettlement` / `deliverReport`) + the dae review session:

| Channel | Triggered by | Semantics | Cost |
|---|---|---|---|
| `report` tool | the child, mid-run | Queues for a **later** parent turn only (does not conclude the child's turn); a mid-run relay | one injection per call |
| settlement notice `subagent-settled` | the runtime, at Activation settlement | **Unconditional**: end_turn / token ceiling / model failure / cancellation / teardown all notify; carries the stop reason + the full final assistant message | exactly one per child |

- **Wake mechanism**: idle parent → `followup` opens a new turn automatically; running parent → `steer` injects into the current turn. ⇒ **Ending the turn to wait has zero loss risk** (field-tested: post-final-turn report/settled each woke a short turn that completed integration).
- **Dual-channel redundancy (field-tested pitfall)**: a child that "`report`s the full text AND puts it in the final message again" costs the parent both injections + two wake turns (dsh-subagent README: *"A child that both reports and settles costs the parent both"*). Paradigm convention (in persona): **single-channel delivery** — the final message is the report; don't `report` the same text.
- **Sleep-wait anti-pattern (field-tested pitfall)**: 8× `sleep 45~240s` pinning the turn while waiting = pure wasted latency. Correct shape: independent work exhausted → short status → end the turn and wait for the wake. kix-orchestration v4 one-shot reminds on "bare sleep + description mentioning subagent" (0% false positives: backoff/lock-wait sleeps don't match; v4.1 is platform-agnostic — both command shapes always tested on any tool's `command`).

### §3.2 Arranger model & member menu (2026-08-17, four-round convergence)

The DSH landing of the CEO "pick members" power: **the main model is the arranger; reviewer/dev/qa are resident member contracts; low-frequency capabilities are activatable tiers**. The fixed producer→dev→qa pipeline is a heavy-path convention, not a paradigm invariant. A 2026-09-03 cross-implementation user observation found that resident generic subagent plus hidden members creates role drought, so matching member contracts are now preferred; generic subagent is reserved for unowned Explore/research.

| Member tier | Name handle | Contract (distilled from agents/*.agent.md — the file stays the single source of truth) | Availability |
|---|---|---|---|
| `subagent_dev` | Nova/Sage/Milo three-in-one | code per plan, write inside target_rules, no scope creep, never sign for QA; run deterministic gates per task | resident, direct call |
| `subagent_qa` | Ivy | never business source code, evidence gate, signoff artifacts (PASS/CONDITIONAL/FAIL/REVERIFY_REQUIRED evidence-bound) | resident, direct call |
| `subagent_reviewer` | unnamed | read-only + three-layer devil's advocate (L1 rebuttal rehearsal / L2 depth probe / L3 language-model stress) + rebuttal output | resident; concurrent instances may carry distinct lenses |

**Three deliberate non-rows**: no producer row (S7 proved CEO self-planning usually suffices; for Remy-grade planning the main thread reads `agents/kixpower-producer.agent.md` once); no orchestrator row (coordination stays in the main thread — the DSH main agent has the full orchestration toolset; materializing a coordinator subagent = hiring someone to coordinate yourself); dev as one three-in-one tier (Nova/Sage/Milo switching already lives in one agent body).

**Four floor invariants** (free composition never erodes; see the persona Arranger Model section): ① observation independence (phase duality) — you compose hands, eyes never self-attest; ② coordination stays in the main thread; ③ perspectives come from prompts, not names — material review lane count and concurrency are the model's call from information gaps and capacity — never a preset count, each with a distinct lens; cross adds provider independence and may add/replace one lane but never replaces the reviewer contract; ④ the gate floor is composition-independent (human confirmation before publish/merge/destructive, kix-guards/kix-discipline unchanged, team output is still claims).

**Drift antidotes (no new gates)**: say the composition out loud (who + why) + persist it in the `mode` field of `kix_discipline_spec` (members + one-line reason, added 2026-08-17, optional) + observe the composition distribution under rules-are-liabilities (over-composition and default-solo both get harvested). Mid-flight mis-composition → re-route once and say it.

## §5 Native orchestration

- Complex multi-stage orchestration → `workflow` (phases/pipeline/parallel); long-horizon goals → `goal`; planning first → plan mode; long tasks → `pwsh run_in_background` + `job_output`.
- Full-flow suggestions (new project / full PR review / continue sprint) → suggest the matching `/kixpower-*` command, wait for user confirmation, never auto-trigger.

## §6 PTC / Code Mode (both enabled — red lines)

- Choose the carrier before splitting steps and assess each deterministic segment as a whole. Use `run_code` when multiple results need only a derived answer, bulky or unknown-size intermediates should stay out of context, shared state/control flow/cross-tool transforms matter, or the task needs new ad-hoc JS/TS computation; never wrap that program in `bash node -e`/heredocs. Bash may run existing project scripts, shell-native CLIs, or one self-contained operation whose output is decision-ready. Keep judgment, edits, approvals, external side effects, and stepwise verification native. Use workflow for complex stages; never route by tool quotas.
- Red lines: native JS side effects are not audited action by action, so destructive/release actions must not be hidden in `run_code`; evidence that must remain replayable stays native. Print every decision-relevant result, denied sub-dispatch, and reason; stop on denial; intermediate values do not flow back.

## §6.1 DSH 0.1.5-rc.1 compatibility (2026-09-11, verified on an isolated instance)

Two breaking changes made this preset **unmountable** on 0.1.5-rc.1 (mount throws → no session can be
created → the composer stays inert and kixParadigm becomes unusable). Both are fixed in every preset variant:

| Change | Symptom | Fix |
|---|---|---|
| `@deepseek-ai/dsh-persona` replaced required `text` with required `prefix` (+ `suffix`, sections split into `DEPLOYMENT_PERSONA_PREFIX`/`_SUFFIX`) | `invalid config: $.prefix missing required value` | Persona rows now use a YAML anchor and emit **both** keys from one source; schemastery does not reject unknown keys, so 0.1.2 and 0.1.5 both mount |
| Child `toolFilter.deny` naming `subagent` | `tools.restrict() names unknown global tool "subagent"` on **every** dispatch | `subagent` removed from all tier deny lists; nested dispatch is still refused by kix-cost's `tools.guard` + harness `maxDepth` |

Root cause of the second: `dsh-subagent` calls `composeFrom(childCtx, parent.ctx)`, so the parent preset
registers into the **child's own layer** — and `restrictableNames` excludes own-layer names. `view()` and
`restrict()` are byte-identical in 0.1.2 and 0.1.5, so this was a real defect in both versions, previously
hot-patched only in an installed copy.

Verified on DSH 0.1.5-rc.1: mount succeeds, persona reaches the system prompt, all 7 `kix_*` tools register,
`restrict.applied=true / denyCount=52 / error=null` with 0 `mcp__` tools visible, and a `subagent_lite`
dispatch returns `echo kix-subagent-ok` (exit 0, `autoActivated=true`). The same preset still lists 7 kix
tools on 0.1.2-rc.1.
