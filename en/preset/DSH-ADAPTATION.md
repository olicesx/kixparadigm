## §2 Mechanical guards (resident)

- `plugins/kix-guards.js` auto-mounts a `tools/pre-execute` listener (scope-filtered to this preset) that intercepts: destructive SQL (DROP/TRUNCATE/DELETE/UPDATE without WHERE, statement-level, comment-stripped), dangerous git (force push incl. `-f`/`+refs`/`--mirror`, main-branch pushes, commit-budget via reflog), control-plane file writes (`~/.dsh/**`), unknown execution tools, MCP GitHub remote writes without a feature branch.
- Human-confirmation points (v5, 2026-08-15): `reset --hard`, `clean -f`, `branch -D`, `stash drop`, `checkout --`/`restore`, ordinary pushes, GitHub mutations (e.g. `merge_pull_request`, issue comments) → **asked inside the chat** via `ctx.userQuestions.ask()` (the service behind `ask_user_question`), not the approval dialog. The user answers 「允许执行/拒绝」; the gate then allows or denies. Fail-safe: no `userQuestions` service / no agent / subagent DELEGATED_CALLER / aborted → deny.
- The harness's sandbox stack is the resident mechanical layer on top; the approval policy for `danger-full-access` is `never` (fully automatic, no approval dialogs).

## §2.1 Discipline & orchestration gates (pluginized, 2026-08-16)

- **`plugins/kix-discipline.js`** (43 assertions): the requirement grill & verification gate moved from prompt preaching to enforced mechanism. `tools/pre-execute`: implementation edits (`edit`/`write`) check for a requirement contract (spec) on record — no spec + first implementation edit → `remind` (default: allow + one-shot reminder injected via post-execute) / `ask` (in-chat question) / `block` (deny); test files always pass. `kix_discipline_spec` tool records the triple-check contract (goal/xy/assumptions/path/acceptance, matching kix ①XY ②premise ③path) into workspace `kix-discipline/spec.md` (visible across sessions). `agent/turn-stopping`: a turn ending with implementation edits but no test run gets the delivery-three-questions green reminder (remindOnce). `/kix-discipline status|report|on|off`. Intensity defaults to `remind` (fewer constraints; literal low-risk reversible tasks may ignore the reminder — matches kix signal-based triggering); `ask`/`block` need explicit config on the `agent.cordis.yml` row. Boundary: agent-scope mounted, does not cover subagent sessions (same as kix-guards).
- **`plugins/kix-orchestration.js`** (25 assertions): orchestration handoff gate — a bounded port of Copilot's `validate-handoff.ps1` core. `tools/pre-execute` on `subagent*` dispatch carrying `current_sprint` validates: workspace `docs/.kixpower-current-sprint` marker exists & matches, `docs/sprint-N/{plan,progress}.md` exist (planning done before Dev/QA), `progress.md` has no blocker (`status: blocked` / `blocked_tasks>0` / `❌ Blocked`), QA handoff requires `completed_tasks == total_tasks`. Default `remind`; `ask`/`block` configurable. `/kix-orchestration status|on|off`. **Not ported** (bound to Copilot's runSubagent+agentName dispatch format; over-porting = liability, see PLUGINIZATION-ROADMAP.md): worktree registration / plan_snapshot_sha / l2_gate_manifest_sha256 / stash baseline / reverify marker deep checks.
- Copilot hooks status: of the 9 `hooks/*.ps1`, blast-radius → kix-guards; validate-handoff core → kix-orchestration; role-boundary hooks (block-source-edit / block-dev-authority / block-source-edit-qa) stay as prompt hard constraints (DSH subagents carry no role marker); validate-qa-signoff / qa-freshness / cleanup-qa-session / auto-update-progress have no DSH equivalent flow — not ported. Full audit: `PLUGINIZATION-ROADMAP.md` (EN condensed; CN full edition in the CN preset, incl. migration-completeness audit §6.1).
- **`plugins/kix-focus.js`** (32 assertions): minimal + progressive disclosure + PTC synergy (P4, 2026-08-16). Phase 1 `tools.restrict({ allow })` trims the per-turn tool surface from ~85 (~108KB schema, est. ~30.8K tokens) to the resident core — **allow lists only GLOBAL tools** (`RESTRICT_ALLOW` ~11: edit/write/pwsh/read/grep/glob/ask_user_question/todo_write/skill/web_search); the subagent×5 and kix_capability_* rows are **scope-registered and auto-visible — not listed in allow** (DSH restrict contract fails on scope-local names). MCP (GitHub/Playwright/Context7/Semgrep), workflow/goal/ralph/job_*/cordis_* stay on demand; `tools/change` retry; measured **-81.6%** (`scripts/quantify-focus.cjs`). Phase 2 `kix_capability_search` (GLOBAL view `schemas(undefined)` lists trimmed tools; group metadata without full schemas) + `kix_capability_call` (`get(name, undefined)` global existence check; proxy via `ctx.tools.execute` — full pre-execute→guards→execute→post-execute, gates still fire; **propagates `rootCallId`** for nested execution-tree attribution; agent-carrying calls are not model-direct so no UNKNOWN_TOOL). **Sensing design (revised 2026-08-16): NO pre-execute deny** — restrict already hides trimmed tools from the model (direct calls = UNKNOWN_TOOL before pre-execute) and capability_call's nested sub-calls must pass; guidance rides the call return + persona trigger phrases. Phase 3 keeps `tool-presentation mode: both`; kix red line "verification/observation stay native (evidence replayable)" unchanged; capability_call is also callable from run_code SDK sub-dispatches (which pass through gates). Config: `enableRestrict: false` disables trimming (search/call only); `extraResidentTools` appends. Guards interaction: capability_call/search are in `KNOWN_SAFE_TOOLS` (defensive); every proxied sub-call still passes kix-guards.

## §3 Delegation, cost tiers & vision

- **Cross-vendor observer**: three-channel observation / highest-confidence claims / platform-library semantics assertions → `subagent_cross` (GLM-5.3, cross-vendor contradiction). Ordinary dispatch → `subagent` (inherits the main model). `workflow`'s `agent(prompt, {provider, model})` overrides per call. Since v5.9 the cross/vision/thinker rows pin only a `kix-route:<tier>` sentinel model name; `plugins/kix-route.js` resolves it in the child's first agent/request waterfall against the live llm catalog — cross = vendor inverted from the parent, vision = first model declaring image input, thinker = deepseek preferred. **Boundary semantics (v5.9.1: fail when the role's core capability is missing, degrade when the role still stands)**: cross in a single-vendor deployment (no foreign provider registered) and vision with no image-declaring model anywhere FAIL AT START — the error lists registered providers plus what to do instead (plain subagent same-vendor review with an explicit caveat / configure the provider) and reaches the parent via the failed run; never silently degrade to same-vendor (false independence is worse than failure). Thinker without deepseek degrades to the environment default route (the big-budget deep-thinking role still stands) with a one-time warning; resolution failures are not cached (a provider registered mid-session takes effect on the next request); a missing plugin fails LOUD on the sentinel (UNKNOWN_MODEL). The old "exact pair" rule was a declarative-layer constraint (agentOptions custom keys are stripped by zod); the waterfall layer can rewrite the whole config (kix-cost's lite fallback proved the same seam). The candidate pool is the `llm-pi-ai:` list of `settings.yaml` plus the pi-ai built-in catalog; model-line upgrades only touch settings.
- **Cost tiers (v5.8)**: `subagent_lite` = slim composition (mechanical persona ~60 tokens shadows the ~17k resident persona; `toolFilter` trims 82 tools / 17.2k tokens down to read/grep/glob/pwsh / 1.6k tokens) → per-step fixed overhead ~34.3k → ~5.9k tokens (↓83%, measured). Preferred route `zai-coding-cn/glm-4.7` is **auto-probed** by `plugins/kix-cost.js` on the child's first request (`llm.listProviders` + `resolveModelInfo`); when unavailable (other environments) it falls back to the environment default route (`agentDefaultModel.currentSelection()`). `subagent_thinker` (deepseek-v4-flash, 128K cap) is the same-family max-effort tier.
- **Effort normalization (`plugins/kix-cost.js`)**: deepseek children without an explicit effort get `reasoningEffort` injected by budget cap — `subagent_thinker` (≥98K) → `max`, others (64K) → `high` (the adapter default is high/256K; the 64K cap is the runaway guard). GLM children are adapter-managed; the main session (explicit effort from `settings.yaml` `agent-default-model.reasoningEffort`, default `high`) and any explicit per-session selection are never touched. Runs on the `agent/request` waterfall; unit tests: `node plugins/kix-cost.test.js`.
- **Vision**: the main model declares no image input, so `read_image` is rejected by the routing gate. To inspect images (screenshots / error images / charts / UI / OCR) → pass the image path + question to `subagent_vision` (auto-routed to the first image-capable model).
- **UI image upload**: the profile plugin `dsh-vision-bridge` (installed by the npm package) converts pasted/dropped images to text descriptions at send time; messages arrive prefixed `📷 [图片自动识别]` — plugin output, not the user's words. If the description is insufficient, ask the user for the image path and use `subagent_vision`.
- Both `subagent_cross` and `subagent_vision` route through `llm-pi-ai.providers` in `settings.yaml` — see §Settings.

## §4 Settings.yaml (host plane — the preset cannot install it)

`~/.dsh/settings.yaml` must contain, under `llm-pi-ai.providers`:

- `zai-vision`: GLM-4.6V vision provider — `api: openai-completions`, `baseURL: https://open.bigmodel.cn/api/coding/paas/v4`, models `glm-4.6v` / `glm-4.6v-flash` / `glm-4.5v` each with `input: [text, image]`; API key via env `ZAI_CODING_CN_API_KEY` or `~/.dsh/.credentials.yaml`.
- `zai-coding-cn`: GLM-5.3 cross-vendor observer (text) — `models` list declares glm-5.3 / glm-5.2 / glm-5.1 / glm-5-turbo / glm-4.7 / glm-4.5-air.

Without these, `subagent_cross` / `subagent_vision` cannot route. The installer (`kixparadigm-en`) reports this checklist; `kixparadigm-en doctor` re-checks it.

## §5 Native orchestration

- Complex multi-stage orchestration → `workflow` (phases/pipeline/parallel); long-horizon goals → `goal`; planning first → plan mode; long tasks → `pwsh run_in_background` + `job_output`.
- Full-flow suggestions (new project / full PR review / continue sprint) → suggest the matching `/kixpower-*` command, wait for user confirmation, never auto-trigger.

## §6 PTC / Code Mode (both enabled — red lines)

- `run_code` is for mechanical multi-step / batch / concurrent read-only probes; **verification and observation stay native** (evidence must be replayable, gates visible one by one).
- Red lines: verification evidence must be re-run natively or handed to an independent observer; the program must print all context later steps need (including denied sub-dispatches and reasons); on denial, stop immediately — never silently swallow a denial; intermediate values do not flow back.
